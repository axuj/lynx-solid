# HackerNews

A HackerNews client with feed pages, item threads, user profiles and route-level loading states — the mid-size showcase between the counter tutorial and full Elk. It demonstrates file-based routing, async queries and Lynx list rendering against the public HackerNews JSON API.

## Overview of Changes

Most code transfers directly — component logic, file routing and Solid reactivity work identically. Changes relative to the web shape:

| Aspect | Web shape | Lynx Solid |
|--------|-----------|------------|
| **Template elements** | `<div>`, `<span>`, `<img>`, `<a>` | `<view>`, `<text>`, `<image>`, tap events |
| **Event handling** | `onClick` | `bindtap` |
| **Router history** | History API | `createMemoryHistory()` |
| **Scrolling** | Native browser scroll | `<list>` / `list-item` with `item-key` |
| **Data fetching** | `fetch` + local state | `fetch` + signals (`use-hn-query` helper: cache, dedupe) |
| **Build tool** | Vite / Webpack | Rsbuild |
| **SSR** | Server render + hydration | None (Lynx doesn't SSR) |

## How it's built

- **File-based routes** — `src/routes/` maps to screens: `$feed.tsx` + `$feed.$page.tsx` (paginated feeds), `item.$id.tsx` (comment threads), `user.$id.tsx` (profiles), all under `__root.tsx`. The table is generated by `@tanstack/router-plugin` (Generator half only — no code splitting, Lynx bundles stay single-file).
- **Memory history** — `createMemoryHistory({ initialEntries: ['/news'] })` with `isServer: false`: Lynx has no History API, and the explicit opt-out keeps the router off its SSR path. See [Routing](/guide/routing).
- **Async queries** — `src/composables/use-hn-query.ts` is a Solid 2 async helper (signals + two-arg effect, module cache with stale time, in-flight dedupe) exposing data / isLoading / isFetching / isError; pages render `Spinner` → `NewsItem` / `Comment` states like a web app.
- **Lynx lists** — feeds render through native `list` / `list-item` with `item-key`, so long threads scroll and recycle natively.

## What it proves

Routing + async + lists compose without DOM escape hatches: no `window.location`, no `URLSearchParams` polyfill (the router's bundled query parser covers it), no code-splitting. If your app fits this shape — browse, drill in, paginate — copy `src/router.tsx` and `src/routes/` as the starting skeleton.
