# Elk — a Mastodon Client

To prove Lynx Solid can carry a real product-grade app, we ported [vue-lynx's Elk example](https://github.com/Huxpro/vue-lynx/tree/main/examples/elk) (Apache-2.0) into a **native Mastodon client** — which is itself a port of [Elk](https://github.com/elk-zone/elk) (MIT), the beloved Mastodon web client by Anthony Fu and team. We reuse Elk's framework-agnostic layers (masto.js API client, Mastodon-HTML content pipeline, domain logic, theme) and rebuild its UI on Lynx native elements. It browses any public Mastodon instance as a guest (default `mas.to`): timelines, threads, profiles, search, trends, dark mode and more.

Try it below. The **Web** tab runs the real app on Lynx for Web against a live instance; the **QR Code** tab runs the same bundle natively — scan it with Lynx Explorer (see [Quick Start](/guide/quick-start) to install one).

## Guest session before first render

`src/index.tsx` establishes an anonymous masto.js session against the default public instance before mounting, so the first paint already has a timeline to show:

```tsx title="src/index.tsx"
import { mastoLogin } from './composables/masto'
import { DEFAULT_SERVER } from './composables/users'

// Anonymous session against the default public instance — Elk's guest mode.
// Sign in from Settings (server + access token) for home/notifications/votes.
mastoLogin({ server: DEFAULT_SERVER })

render(() => <App />)
```

`App` itself is a one-liner over the router (`src/App.tsx` renders `<ElkRouter />`). Authenticated features — home timeline, notifications, favouriting — unlock from Settings with a server + access token; everything else works as a guest.

## File-based routes, memory history

`src/routes/` declares one file per screen — `home`, `notifications`, `search`, `settings`, `$server.public`, `$server.status.$id`, … — generated by `@tanstack/router-plugin` (Generator half only, so the bundle stays single-file) and served through `createMemoryHistory` with `isServer: false`. See [Routing](/guide/routing) for the full pattern.

## Native rendering of web-shaped data

Two layers translate the Mastodon web model into Lynx elements:

- **Timelines** (`src/components/TimelinePage.tsx`, `CollectionPage.tsx`) render through native `list` / `list-item` with `item-key`, so long feeds scroll and recycle natively; pagination state lives in `src/composables/paginator.ts`.
- **Post content** (`src/content/content-render.tsx`) parses Mastodon HTML with ultrahtml and emits `<text>` runs via `contentToJSX()` — mentions, hashtags and links become tappable spans, block tags become stacked text blocks. No WebView anywhere.

The surrounding chrome — bottom tab bar (`NavBottom.tsx`), page headers, sheets — is Lynx elements with `bindtap` navigation, so the whole app is a single element tree.

## What it proves

Elk exercises everything at once: async data + routing + lists + media + settings persistence + dark mode. If a runtime change keeps Elk green, the binding is product-ready. Browse the 70+ source files in the preview's file tree — `src/composables/` holds the domain logic, `src/components/` the UI kit.
