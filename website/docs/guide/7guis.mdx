# 7 GUIs

To verify that Lynx Solid behaves identically to Solid in real GUI scenarios, we ported the [7 GUIs](https://eugenkiss.github.io/7guis/) tasks from the [official Solid examples](https://www.solidjs.com/examples) family — seven classic tasks covering typical GUI challenges, from a simple counter to a full spreadsheet. Each task is its own entry; switch entries in the preview's entry selector.

## Examples

### 1. Counter

A simple button that increments a counter. Tests basic state management and event handling.

A flight booking form with conditional validation. Tests constraints, conditional visibility, and input validation.

### 4. Timer

An elapsed-time gauge with adjustable duration. Tests timers, competing user/signal interactions, and continuous updates. The interval is registered in the component body and released with `onCleanup`; callbacks take no forwarded arguments (a PrimJS requirement — see [Introduction](/guide/introduction)).

<Go example="7guis" defaultFile="src/timer/index.tsx" entry="src/timer" defaultEntryName="timer" />

### 5. CRUD

A filterable list with create, read, update, and delete operations. Tests managing a dynamic collection of data. Selection side-effects use Solid 2's two-arg `createEffect` (track in compute, apply in the second fn — the same shape as Elk's router bridge).

<Go example="7guis" defaultFile="src/crud/index.tsx" entry="src/crud" defaultEntryName="crud" />

### 6. Circle Drawer

Draw circles on a canvas with undo/redo support. Tests custom drawing, a non-trivial undo model, and dialog control flow. Canvas taps use `bindtap` with coordinate fallbacks; per-circle taps use `catchtap` so they never reach the canvas.

<Go example="7guis" defaultFile="src/circle-drawer/index.tsx" entry="src/circle-drawer" defaultEntryName="circle-drawer" />

### 7. Cells

A simple spreadsheet with formula evaluation. Tests change propagation, cell references, and reactive computation. The grid lives in a `createStore` so each cell tracks its own path; `=A0+B1` formulas evaluate through the same `new Function` sandbox as the reference implementation.
