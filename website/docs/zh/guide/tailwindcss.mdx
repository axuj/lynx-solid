# 使用 Tailwind CSS

[Tailwind CSS](https://tailwindcss.com/) 是一个实用优先的 CSS 框架。结合 Lynx Solid，它让你可以使用与 Web 端相同的工具类来构建原生 Lynx UI。

本指南将介绍如何将 Tailwind CSS 与 Lynx Solid 集成，从基础配置到设计令牌系统以及运行时主题切换。下面的专用 demo 跑的是完整配置：preset、插件、token、三主题切换全有：

## 配置

### 1. 安装依赖

<PackageManagerTabs command="install -D tailwindcss@3 @lynx-js/tailwind-preset rsbuild-plugin-tailwindcss" />

:::tip 需要 Tailwind v3
`@lynx-js/tailwind-preset` 和 `rsbuild-plugin-tailwindcss` 需要 **Tailwind CSS v3**。Tailwind v4 采用了完全不同的架构，目前尚不支持。请确保你**没有**安装 `@tailwindcss/postcss`——那是 v4 专用的包，与 v3 配置不兼容。
:::

- **`@lynx-js/tailwind-preset`** — 一个 Tailwind 预设，用 Lynx 兼容的替代方案替换核心插件。详见[官方文档](https://lynxjs.org/rspeedy/styling.html#using-tailwind-css)。
- **`rsbuild-plugin-tailwindcss`** — Tailwind CSS 的 Rsbuild 集成插件（HackerNews 示例中即按此接入，无需手写 PostCSS 配置）。

### 2. 配置 Tailwind

```ts title="tailwind.config.ts"
import type { Config } from 'tailwindcss'
import preset from '@lynx-js/tailwind-preset'

const config: Config = {
  content: ['./src/**/*.{tsx,ts,jsx,js}'],
  presets: [preset],
}

export default config
```

### 3. 添加 Rsbuild 插件

```ts title="rsbuild.config.ts"
import { defineConfig } from '@rsbuild/core'
import { pluginSolidLynx } from '@lynx-solid/plugin'
import { pluginTailwindCSS } from 'rsbuild-plugin-tailwindcss'

export default defineConfig({
  plugins: [
    pluginSolidLynx(),
    pluginTailwindCSS({
      config: 'tailwind.config.ts',
      exclude: [/[\\/]node_modules[\\/]/],
    }),
  ],
})
```

### 4. 在 CSS 中引入 Tailwind

```css title="src/App.css"
@tailwind base;
@tailwind utilities;
```

配置完成！现在你可以在 Lynx 元素上使用 Tailwind 工具类了：

```tsx title="src/index.tsx"
<view class="p-4 flex flex-col gap-2">
  <text class="text-blue-500 text-lg font-bold">Hello, Tailwind!</text>
  <view class="bg-gray-800 rounded-lg p-3">
    <text class="text-white text-sm">A card with utility classes.</text>
  </view>
</view>
```

## 使用 CSS 变量的设计令牌

现代组件库中常见的模式是将**设计语言**定义为 CSS 自定义属性，然后在 Tailwind 中引用它们。这为你提供了一个颜色的单一事实来源，并且可以在运行时进行切换。上面的 demo 正是如此：

### 定义令牌

```css title="src/App.css"
@tailwind base;
@tailwind utilities;

:root {
  --color-background: rgba(9, 9, 11, 1);
  --color-card: rgba(24, 24, 27, 1);
  --color-card-foreground: rgba(250, 250, 250, 1);
  --color-primary: rgba(255, 100, 72, 1);
  --color-primary-foreground: rgba(255, 255, 255, 1);
  --color-border: rgba(63, 63, 70, 1);
}
```

### 将令牌接入 Tailwind

```ts title="tailwind.config.ts"
const config: Config = {
  // ...
  theme: {
    extend: {
      colors: {
        background: 'var(--color-background)',
        card: {
          DEFAULT: 'var(--color-card)',
          foreground: 'var(--color-card-foreground)',
        },
        primary: {
          DEFAULT: 'var(--color-primary)',
          foreground: 'var(--color-primary-foreground)',
        },
        border: 'var(--color-border)',
      },
    },
  },
}
```

现在 `bg-primary`、`text-card-foreground`、`border-border` 都会通过你的 CSS 变量来解析。`:root` 中的值作为默认主题。（HackerNews 示例是同一模式的 `hn-*` 命名空间版。）

### 必需的 Lynx 标志

要在 Lynx Native 上使 CSS 变量生效，必须启用两个引擎标志：

- **`enableCSSInheritance`**——让*常规*可继承属性（font-size、color……）从父到子级联，与 Web 一致；主题改了根上的这些属性、期望子元素跟随时开启。自定义属性（`--*`）**与本标志无关**，无条件继承——引擎在门检查之前就复制它们（`StyleResolver::InheritParentStyle`）。详见 [Lynx CSS 变量文档](https://lynxjs.org/api/css/properties/css-variable.html)。
- **`enableCSSInlineVariables`**——门控经内联样式的运行时 `--*` 写入（方式 A 的 `style` 绑定 / 方式 B 的 `setProperty`）及其覆盖的重新级联，主题切换运行时生效。

```ts title="rsbuild.config.ts"
pluginSolidLynx({
  enableCSSInheritance: true,
  enableCSSInlineVariables: true,
})
```

> 两个标志与变量的*可见性*本身无关：样式表里定义的自定义属性（`:root`、class 规则）两个都不开也已到达后代。静态颜色值（例如 `primary: '#3b82f6'`）则完全不需要标志。

## 运行时主题切换

通过 CSS 变量连接设计令牌后，切换主题只需覆盖变量值即可。

### 方式 A：内联样式（推荐）

最接近 Web 端习惯的方式——通过 `style` 绑定在根元素上设置 CSS 变量。这也是 shadcn/ui 和 Radix Themes 在 Web 端处理主题的方式。

需要 `enableCSSInlineVariables`——`--*` 写入走内联样式存储，引擎只在该标志开启时收集它。只有 style 对象同时设置了你期望子元素继承的常规可继承属性（font-size、color……）时才再开 `enableCSSInheritance`；纯 `--*` 主题只需 InlineVariables。

```tsx
import { createMemo, createSignal } from 'solid-js'

const themes = {
  dark: {
    '--color-background': 'rgba(9, 9, 11, 1)',
    '--color-primary': 'rgba(255, 100, 72, 1)',
    // ...
  },
  light: {
    '--color-background': 'rgba(255, 255, 255, 1)',
    '--color-primary': 'rgba(234, 88, 12, 1)',
    // ...
  },
}

function ThemedApp() {
  const [currentTheme, setCurrentTheme] = createSignal<'dark' | 'light'>('dark')
  const themeStyle = createMemo(() => themes[currentTheme()])

  return (
    <scroll-view style={themeStyle()} class="bg-background">
      <text class="text-primary">Themed text</text>
      <view bindtap={() => setCurrentTheme('light')}>
        <text>Switch to Light</text>
      </view>
    </scroll-view>
  )
}
```

### 方式 B：元素 `setProperty` API

一种 Lynx 原生的替代方式，直接在元素上更新 CSS 变量，不经过 `style` 绑定。它仍需要 **`enableCSSInlineVariables`**——`setProperty` 写的是同一套内联自定义属性存储，引擎按该门收集（后代随后经*无条件*的自定义属性继承读到它们，所以让它们可见的不是 `enableCSSInheritance`）。拿到元素（经 `main-thread:ref` 或选择器查询）后把整组变量一次性传给它的 `setProperty`，其下所有 `var(--color-*)` 消费者重新级联。这条路径尚未在我们的 runtime 上验证过——除非有实测理由，否则优先用方式 A。

详见 [Lynx CSS 变量 API](https://lynxjs.org/api/css/properties/css-variable.html) 了解 `setProperty` 的完整文档。

### 方式 C：按 class 切换（上面的 demo 即此方式）

上面的 demo 靠根节点上一个 class 在三个主题（dark / light / ocean）间切换，由 signal 驱动：

```tsx
const [currentTheme, setCurrentTheme] = createSignal<'dark' | 'light' | 'ocean'>('dark')
const themeClass = createMemo(() => `theme-${currentTheme()}`)

<scroll-view class={`w-full h-full bg-background ${themeClass()}`} …>
```

```css
/* Dark 即 :root 默认值；light/ocean 覆盖它。 */
.theme-light { --color-background: rgba(255, 255, 255, 1); /* … */ }
.theme-ocean { --color-background: rgba(15, 23, 42, 1); /* … */ }
```

点击主题按钮翻转 signal；class 跟随变化，其下所有 `var(--color-*)` 消费者同步切换，无需改动 bundle。需要开启上述两个标志（Elk、HackerNews 与 tailwind 示例的配置均已开启）。Elk 示例是同一模式的双主题版（`.app-dark` 覆盖 `:root`）。

详见 [Lynx CSS 变量 API](https://lynxjs.org/api/css/properties/css-variable.html)。

## 常见问题

### 新的 Tailwind 类在热更新时不生效

**症状：** 你将 `bg-slate-800` 改为 `bg-red-500` 并保存，但模拟器没有更新。切换_回_之前用过的类可以生效，但新的类在重启开发服务器之前不会显示。

**原因：** Tailwind v3 的 JIT 编译器只为源文件中找到的工具类生成 CSS。当文件变更时，JIT 需要重新扫描并生成新引用的类。

最常见的原因是**混用了 Tailwind v3 和 v4 的包**：

| 包 | 版本 | 说明 |
|---|------|------|
| `tailwindcss` | 3.x | Tailwind v3 核心（同时也是 PostCSS 插件） |
| `@tailwindcss/postcss` | 4.x | Tailwind **v4** PostCSS 插件——**与 v3 不兼容** |

这两个不能共存。Lynx 生态（`@lynx-js/tailwind-preset`、`rsbuild-plugin-tailwindcss`）需要 **Tailwind v3**。

**修复：** 移除 v4 包：

```bash
nub remove @tailwindcss/postcss
```

然后按照[上方的配置步骤](#1-安装依赖)操作。

### `content` 路径未匹配到源文件

如果 Tailwind 类在某些文件中生效但在其他文件中不生效，请检查 `tailwind.config.ts` 中的 `content` 数组是否包含了所有相关路径：

```ts
content: ['./src/**/*.{tsx,ts,jsx,js}'],
```

如果你的源文件在其他位置（例如 `pages/`、`components/`），请相应调整 glob 模式。
